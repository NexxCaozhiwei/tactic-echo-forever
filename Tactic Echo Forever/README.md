# Tactic Echo Forever 2.0.1

当前基线包含列表循环、优先级推荐、每种来源三套独立方案、技能组、增益维护、共享策略编辑器和 HUD 预览。

输入 `/tefui` 打开TEF Studio。保存并关闭设置后，左键 HUD 主技能图标或使用启停快捷键开启派发；`/tef resume` 保留进度开启，`/tef stop` 停止。设置期间不发布输入请求。

技能组每处独立保存：最多8步，每步1～99次、整组1～99轮；精确成功推进，失败不推进。组进入后保持顺序，增益维护可在当前施法结束后插入。手动首发符合当前组与策略时接续回执，飞弹等引导结束后才进入下一轮。编辑、重载、世界切换清除组进度。

增益维护高于战斗来源，脱战需要手动开启派发；CDM未知不补增益。普通战斗技能组仍须公开战斗状态。技能等级、可用性、资源、目标、范围与回执身份检查保留，不从未知推断就绪。

仓库根目录 README 提供完整安装与构建说明，`docs/baselines/tef/BASELINE_2.0.1.md` 记录基线范围，`docs/SKILL_GROUPS_DRAFT.md` 提供实机验收步骤。离线检查和部署哈希不证明真实游戏派发通过。

## 历史使用说明

修复同一目标策略在GUID无法公开读取时阻断的问题。先公开确认目标存在，再使用目标选择周期作为备用身份；同一次选择只用一次，切换后重新选中同一只怪算新选择。GUID公开时仍支持识别切回已完成目标。目标存在状态未知仍等待，不把受限GUID当作公开身份。新版实际效果待复核。

## 1.0.21 步骤使用策略

人工序列每行新增使用策略按钮，点击在“每轮使用 / 同一目标只用一次 / 同一战斗只用一次”之间切换，保存后生效。完成该步骤全部次数才登记；失败或阻断不消耗。B按目标限制时，首次ABCD后同目标循环为ACD，换新目标可用B，切回旧目标仍跳过；按战斗限制时，换目标也跳过，确认脱战后恢复。

暂停及自然循环保留记录；主动重置、编辑、重新开始、世界切换或reload清除。限定步骤部分次数不跨目标或战斗累计；未知身份或战斗状态等待确认。高级文本例子：205:205*3!skip!target，205:205!combat。

## 1.0.20 攻击开启与范围修复

攻击6603按公开自动攻击开启状态确认一次后立即进入下一步，次数固定为1；已经开启不会重复按键关闭，不统计平砍命中。自动脱战待命可确认手动开启，但不发按键；暂停、设置打开或未知状态不推进。普通技能仍按精确成功回执计数。

## 1.0.19 圣印与窗口修正

修复人工序列里圣印等自身技能被敌方范围门禁误拦的问题。自身分类依据公开的0/0技能范围及友方/敌方技能标记，未知信息仍等待；资源和可用性仍需确认，审判等目标攻击技能继续检查目标范围。

## 1.0.18 宏与窗口顺序

设置窗口在打开时提升一次，点击时按游戏自然顺序到前面；普通刷新不会反复抢前台，其他游戏面板重新唤起后可覆盖它。

可以把已有技能宏放在动作栏并绑定按键，再将该宏或动作栏宏拖入人工序列／自定义 APL。插件保存当前公开确认的精确技能 ID，HUD 和 TEK 使用宏现有按键。宏需有可读取的正文，GetMacroSpell 能公开确认其技能 ID，且正文包含该技能的施法引用。仅改提示图标、物品宏或无法确定唯一身份的宏不会接纳。

宏分支和目标由游戏执行，插件不改写宏、不推断宏内状态；仍按实际精确施法成功事件计数。修改宏后会重新核对映射并撤销已失效请求。实际输入与窗口切换待实机确认。

## 1.0.17 编辑体验

推荐配置可从法术书或动作栏直接技能拖入，拖到列表空白处追加，拖到已有行插入该行之前；也可持有技能后点击列表。宏或物品游标不猜测技能 ID，草稿仍需点击保存。

## 1.0.16 手动起手接续

固定序列已启用且处于自动脱战待命时，手动施放当前步骤的技能也会计数：例如 A→B→C→D，手动成功施放 A 后 HUD 转到 B，进战后从 B 接续。重复次数、精确起始/成功身份和去重规则与自动施放一致；脱战待命不自动发按键。

主动暂停、打开设置、重置或配置编辑后不继续计数；只施放其他步骤的技能不会跳步。新增行为通过离线回归，实机验证待完成。

### 自定义APL距离条件

距离条件优先使用已检查且公开的 `UnitDistanceSquared` 精确值；不可得时，与HUD共用固定物品探针，实时取得估测区间。区间下界为开区间，上界为闭区间，例如 `(5,8]` 可确认 `距离<10`，但 `距离<7` 为 `UNKNOWN`。只有整个区间支持比较结果时才返回真或假；不以区间中点冒充精确距离。缺失、受限、友方战斗限制、探针冲突与跨阈值均保持未知。技能自身范围资格仍独立检查，派发前重新采样，不使用HUD历史缓存。

### 后台公开性探测

自定义APL已移除战斗实测受限的蓝量百分比条件和冷却数值检查；旧配置迁移时删除这两类条件，技能顺序及其余条件保留。资源足够仍由技能公开可用性接口独立检查。移动、距离、CDM及公开冷却活动条件继续可用。

在现有有界采样中，后台只读尝试 `UnitHealthPercent("player", true)`，记录原始返回值与公开性原因，不预设返回比例的缩放。对启用且确认已学的规则技能，尝试 `C_Spell.GetSpellCooldownDuration(spellID)`，观察 `IsZero`、`GetTotalDuration`、`GetRemainingDuration` 的公开返回值及原因；同次采样重复技能复用结果，排除61304。

血量和Duration仅为诊断，不参与规则资格或派发，也不推算冷却结束。对象、Secret原值和异常文本均不持久化，仅保存经Safety规范化的标量。缺少接口、方法、Secret及调用失败均明确记录；方法数值变化不单独触发逐帧日志。规则预览展示最近观察，落盘诊断保留清洗结果。无新增定时器、钩子或输入路径。

### 1.1.1新增策略条件

新增战斗状态、当前目标类型、其他精确技能已学、本轮精确成功记录、CDM公开增益层数，以及指定技能范围内可见敌人数。条件可用于使用或跳过策略，未知不授权派发。层数缺失不当作零；范围内计数不代表AoE命中数。成功记录开始／重置／编辑／重载清除，暂停和候选替换保留。详细定义和验收边界见仓库的1.1.1基线。

### 1.1.2姓名板码数只读诊断

自动兼容姓名板单位字段，按配置码数探测每个公开确认的敌方单位，并记录确定数量／可能数量。原技能范围条件自动附带10码诊断；可选“码数内敌人数（只读探测）”填写其他码数。当前新路径仅诊断，条件仍返回UNKNOWN，不授权施放；玩家不用逐个选择姓名板。实际范围公开性和数量变化需落盘验证。

### 1.1.3自身范围内可见敌人数

原技能范围条件及码数只读探测已合并为“自身范围内可见敌人数”，填写自身码数和数量上下限即可用于使用／跳过策略。旧技能范围条件迁移时默认10码，保留数量限制；数量区间跨过阈值时仍为UNKNOWN，派发前重新检查。不代表魔爆真实命中数，10码也不自动等同于技能半径。

## 1.1.4失控门禁

APL自动检查每个技能的公开失控冷却状态，失控或未知时不派发该技能，其他合格技能继续按优先级选择。无需新增策略条件。诊断字段loss_control_clear为false表示公开失控，true表示公开解除，缺失表示UNKNOWN；lossControlReason说明原因。部署后/reload，再复现学派禁用并落盘验证。
