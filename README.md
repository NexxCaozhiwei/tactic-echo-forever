## 项目介绍

Tactic Echo Forever（TEF）在游戏内编排技能、检查条件并显示推荐，通过独立的 TEF TEK 桌面程序联动现有动作栏按键。插件、桌面工具和构建脚本均位于本仓库，可独立安装和构建。

**当前基线：2.0.1。** 面向 Forever / Infinite 的职业、天赋与已学技能模型，目标客户端为公开版本 `1.60.1 / Interface 16001`，构建号用于诊断。全职业自定义主动技能可通过公开身份与施放类型接入；这不代表所有职业、技能等级和客户端接口已经逐项实测。

## 主要功能

| 功能 | 行为 |
| :--- | :--- |
| 列表循环 | 按顺序执行，最多16个父列表项；普通技能每步1～99次，支持不可用跳过、按目标／战斗限制、暂停与循环。 |
| 优先级推荐 | 从上往下选取符合条件的规则，普通技能成功后重新判断；最多16项，可插入顺序技能组。 |
| 三套独立方案 | 两种战斗来源各有三个配置槽，支持自定义名称；同一时间择一运行，默认启用方案一。 |
| 技能组 | 作为父列表的一行，组策略决定进入；组内顺序、次数、跳过与有限循环独立设置，完成后返回父列表。 |
| 增益维护 | 独立增益列表，优先于两种战斗来源；脱战需要手动开启派发，未知增益条件不会授权补放。 |
| 共享策略 | 支持使用／跳过策略，条件包括技能可用性、范围、目标距离、移动、敌人数、CDM冷却／增益、失控、战斗、目标类型、已学和成功记录；连击点条件仅盗贼显示。 |
| HUD与诊断 | 主推荐及两个候选图标、键位、范围变色、公开冷却、组内进度和阻断原因；图标大小及间距支持滑动与数值输入，启停有音效。 |
| 已有技能宏 | 可拖入有公开精确技能身份的动作栏宏，核对正文与按键后使用现有绑定；不生成或修改宏。 |
| 普通读条末尾排队 | 列表循环普通技能可选0～0.50秒提前量，受客户端排队窗口限制；不跨组入口，组内、优先级普通规则、引导及魔杖不提前预测。 |

使用策略的条件必须全部满足，任一跳过策略满足则跳过。未知不等于条件不满足，也不等于可用；对应步骤或规则保持等待或不获选。

提前排队仅接纳已确认的普通施放类型；引导、地面引导及未知类型不提前预测，但仍可按正常路径执行。技能组内“每目标／每战斗”额度与父列表及其他组隔离，同一组的多轮执行保留该额度限制。HUD候选预览始终只读，不会重新武装一次触发策略。

## 快速上手

### 安装游戏插件

将仓库中的 `Tactic Echo Forever` 内层目录放到游戏插件目录，保证没有额外嵌套：

```text
无限版客户端/Interface/AddOns/Tactic Echo Forever/
├─ Tactic Echo Forever.toc
├─ Config.lua
├─ SkillGroups.lua
└─ …
```

在角色选择界面启用 Tactic Echo Forever。替换安装时先备份旧目录；只启用一个 TE／TEF 信号源。插件仅使用自己的 `TEF_DB`，不会读取其他插件设置，不修改 WTF、技能绑定或宏。

### 配置与启停

1. 输入 `/tefui` 打开TEF Studio，在派发总览选择“列表循环”或“优先级推荐”。
2. 选择编辑方案，拖入当前已学的精确技能，设置顺序、次数和策略。启用方案并点击“使用本方案”；当前方案会有明确标记。
3. 将对应技能或已有宏放到有按键的动作栏，保存配置，关闭设置。
4. 左键 HUD 主技能图标，或使用派发总览配置的启停快捷键，手动开启派发。设置窗口打开期间不发布输入。

| 命令 | 用途 |
| :--- | :--- |
| `/tefui` | 打开设置。 |
| `/tef resume` | 保留当前进度开启派发。 |
| `/tef stop` | 停止派发。 |
| `/tef toggle` | 切换派发启停。 |
| `/tef start` | 重置当前循环并重新开启。 |

普通来源默认要求公开战斗；选择“手动模式”并手动开启后，普通技能可以在公开脱战时尝试派发，仍检查目标、范围、资源、文本焦点和施法等门禁。技能组仍要求战斗。自动进入世界不会授予脱战派发资格。自动待命可以监听手动起手；符合当前技能组、策略和精确身份的首发可接续计数，仍须成功回执推进。仅勾选“启用增益维护”不会授予脱战维护资格，脱战维护需手动开启派发。

### 构建桌面工具

在 Windows 使用64位 Python 3.11或更新版本和 PowerShell 7，在仓库根目录执行：

```powershell
python -m pip install -r requirements-dev.txt
```

双击根目录 `TEKEXEBUILD.CMD` 进行检查与构建，成功后运行 `dist/standalone-build/TEK-TEF.exe`。桌面工具需要游戏位于前台，并保留手动输入、信号新鲜度、校验和频率等门禁。构建或启动成功不代表真实输入验收通过。

## 技能组

在两种战斗来源的技能列表点击“新建技能组”。组行的“编辑技能组”在主编辑区打开组内步骤，“编辑策略”在Inspector设置组的进入条件。

组内可拖入技能、按ID新增、拖拽／箭头排序，设置单技能策略、使用次数和不可用跳过。拖到空白处追加，拖到已有技能行时插入其前。提供保存、清空及返回；选择组内条目直接在Inspector编辑策略，返回父列表先暂存，显式保存才持久化。

每组最多8步，每步1～99次；循环轮数1～99，默认一轮，不允许嵌套。例如：

```text
父列表：A → B →【奥术组】→ D
奥术组：奥术冲击一次 → 奥术飞弹一次；循环三轮
实际：A → B → 冲击 → 飞弹 → 冲击 → 飞弹 → 冲击 → 飞弹 → D
```

组进入后保持组内顺序，普通优先级技能不抢占；成功回执推进，失败不推进。飞弹等引导在开始时可能报告成功，下一轮仍等待实际引导结束。组循环与父列表循环分别处理。

优先级中的组完成后从最高优先级重新判断，同一触发状态下不会立即反复进入；组策略明确不满足后再满足、目标选择改变或重新手动开启可重新触发。无条件组每次开启或目标选择周期执行配置轮数。

手动停止保留组进度。目标选择改变、公开死亡或消失会结束当前组；编辑、重置、重载、世界切换或致命错误清除进度。增益维护可在当前施法结束后插入，之后恢复组内位置与次数。

## 距离、增益和验证边界

派发采用“确认起手后等待、普通读条末尾接下一步、精确成功才推进”。在TEK设置页可滑动或手输提前时间（0～0.5秒，0关闭）及失败重试间隔（0～0.5秒，默认0.15秒）。修改参数会停止派发，需重新开启；已有提前时间保留。列表循环仅对已登记普通施放类型排队，不跨技能组、不预测优先级推荐或引导；飞弹等引导结束后再接续。参数含义、边界与验收步骤见[起手确认与派发接续](docs/DISPATCH_PACING.md)。

- 周围敌人数按可见姓名板与物品距离探针判断，半径可选5、10、20、25、30、35、40码内；各档位不代表全部已实测。最近日志确认10码探针在一次测试有效，8码曾全部未知。不能把可见人数当作全场敌人数或实际命中数。
- HUD目标距离是估测区间；策略距离及周围敌人数使用自己的条件采样与派发前复查，HUD显示不直接授予输入资格。
- CDM活动信号不是直接光环真值。技能ID与增益目录ID可能不同；整体隐藏、缺失、受限或冲突均保持未知。精确条目因公开不活动状态自动隐藏的受限例外见下文开发检查。
- 魔杖、自动攻击和自动射击保留开启状态检查；攻击6603确认开启一次后推进，不按平砍命中计数。
- 插件请求、桌面输入与游戏成功回执分别记录。离线模拟、部署哈希及历史实机记录不能代替新增路径的实际验收。

## 开发检查

CDM增益策略区分“增益条目不活动时自动隐藏”和“整个面板隐藏”。精确匹配的条目在父面板公开可见、允许并启用不活动隐藏，且公开活动值为`false`时，按CDM不活动处理，适用于任意增益ID、增益图标与增益条。使用策略要求活动时会跳过该技能；跳过策略要求不活动时也会跳过。缺失、面板隐藏、受限值及冲突仍为未知并暂停；该状态不代表游戏光环真值。

实机验收：将奥术飞弹设为技能组首项，使用条件为CDM增益400588活动，后接奥术冲击。重新加载后选敌对目标并手动开启派发，分别在该CDM增益不活动、活动及再次结束时观察20–30秒；不活动时应顺延，活动时应执行飞弹。另选一个CDM增益重复验证，并在最后重新加载或退出游戏落盘。离线测试与部署校验不等于实机验收通过。

在仓库根目录执行：

```powershell
python scripts/verify-baseline-contract.py --repo-root .
python "Tactic Echo Forever/tests/run.py"
python -m pytest -q tek/tests tests
python -m unittest discover -s tek/tests -q
python -m unittest discover -s "Tactic Echo Forever/tests" -q
python -m compileall -q tek/src tek/app tek/runtime
```

Lua模拟使用 `lupa.lua51`；交付前另做全部Lua文件的5.1语法检查、中文Markdown及差异格式检查。打包插件使用 `python "Tactic Echo Forever/scripts/deliver.py"`，发行包参数见 `python scripts/package-tef-release.py --help`；Windows构建脚本为 `scripts/build-tek-exe.ps1`。

指定安装路径并部署插件：`python "Tactic Echo Forever/scripts/deliver.py" --deploy --target "E:\World of Warcraft\_cn_beta_\Interface\AddOns\Tactic Echo Forever"`。目标必须是已存在的`Interface/AddOns`下的TEF目录；脚本先备份，再复制并核对哈希，不替换活动TEK。

TEAP命名空间为 `TEF`，保留既有v3线格式和唯一输入链；不自动同步正式服TE或替换活动TEK。当前临时 `work/` 为本机开发辅助，不属于正式发行源码。

CDM增益层数条件已移除，旧条件请在游戏内删除或更换后保存；详见[移除说明](docs/CDM_STACKS_REMOVAL.md)。

CDM增益／冷却条件旁新增“选择CDM技能”：从游戏公开目录生成名称与默认观察ID列表，支持搜索、刷新，点击“选”填入当前条件草稿，保存后生效。列表循环、优先级推荐、增益维护及组内条件共用；手输ID继续保留。目录身份与施放技能分开，不自动改写已有条件，不按同名、最高等级或关联技能猜测。详见[CDM默认ID目录](docs/CDM_DEFAULT_ID_CATALOG.md)。

## 标准与迷你HUD

标准HUD为260×108，显示施法名称、施法时间及底部状态说明；预览卡上限为36，与迷你版相同。标准版固定显示步骤与次数，不受旧的隐藏进度行设置影响；迷你版仍遵循该开关。迷你HUD保持156×60。两版右上角8×8按钮可在公开脱战状态下切换，选择保存在TEF自身配置中。迷你版仅显示三图标、键位、状态圆点、固定次数和施法细条；优先级推荐不显示固定次数。主图标悬停保留详情。切换不改变运行意图或列表进度。两版实机视觉与点击效果待验收。

状态徽标区分已暂停、待命、运行、施法、引导、等待回执、具体条件阻断、完成与异常。正常施法不会因原因码包含`UNKNOWN`而显示笼统的“状态未知”；真正无法公开读取施法信息时显示“施法状态未知”。施法门禁仍锁定但显示查询已为空时显示“等待施法结束”，不据此解除派发门禁。其他阻断原因优先保留，原始原因码仍在悬停诊断中。暂停时底部提示派发已关闭；施法信息行保留固定位置以避免施法开始、结束时整个HUD跳动。键位文字相对角标矩形居中。施法条每帧只插值缓存的公开施法时间，文字、距离和图标仍保持原有节拍，不增加施法状态查询或派发。

标准HUD中间新增两排各三个10×10无数字按钮：`[A]`对应优先级推荐，`[S]`对应列表循环，从左到右对应各自的三个方案。当前方案高亮，其余低亮；未启用方案置灰且不能切换，悬停显示完整来源、方案名称与切换说明。增益维护或技能组临时接管时仍标记底层选用方案。切换复用“使用本方案”，停止旧派发并重置进度，需要手动重新开启；重复点击当前方案不重置。按钮组以预览图标的水平中轴线居中，S行的低亮紫色底及边框适度提亮。中间状态徽标缩为短文案，长技能名称按剩余空间缩略以避免遮挡，完整说明保留在底部及原悬停诊断。迷你版隐藏这些按钮。10×10尺寸是用户指定的紧凑设计，用户已反馈按钮布局验收通过。

技能组末步引导期间保留预览卡，避免成功回执先到导致预览提前消失。标签样式仅保留主卡键位、技能名称和进度行，移除隐藏标签及不起作用的锚点、偏移选项；冷却遮罩、距离染红和悬停详情继续保留。旧配置中的有效样式继续加载。详见[HUD预览修复与标签清理](docs/HUD_LABEL_CLEANUP.md)，本轮验证范围见文档中的用户反馈。

HUD设置页已移除覆盖标签卡片的旧摘要。技能库采用独立的不透明深蓝背景，并增加“仅显示动作条上的技能”视图开关：默认关闭，开启后按精确ID筛选已学技能，包含可核对的宏技能，未知身份不收录；不按同名技能合并等级。动作条移动后点击“刷新”重新读取，关闭后再次打开也会重读动作条；输入搜索时使用缓存，不反复扫描。该开关仅影响列表显示，不修改策略草稿、动作条、宏、绑定或运行意图。用户已反馈本轮修改已验证，不扩大为所有职业、分辨率或派发场景均已验收。
