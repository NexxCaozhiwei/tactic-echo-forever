# 列表循环与优先级推荐设置改版

本轮基于 1.1.0 工作区修改，暂不推进版本、提交或推送。离线检查、部署校验与游戏内验收分开记录。

## 称呼、方案与布局

- 界面中的人工序列统一改称列表循环，自定义 APL 改称优先级推荐；内部来源键、协议和原有运行方式保留。
- 页签显示当前使用方案，使用按钮显示正在使用并高亮；编辑另一方案不会悄悄切换运行方案。
- 两种来源分别支持方案名称。名称按职业、来源、方案独立保存，空白恢复默认；最多 64 字节，禁止控制符和竖线。长名称页签缩略显示，名称输入框保留完整内容。
- 增加名称编辑行，调整列表及按钮位置。列表循环增加明显列表与技能条目外框，支持鼠标拖动排序及原有上下箭头。

## 列表循环策略

列表循环每行新增策略条件入口，使用与优先级推荐相同的右侧策略窗口、条件类型及施放类型。每条条件以 AND 组合，全部使用策略必须满足；任一跳过策略满足就跳过当前步骤。旧不可用跳过、每目标／每战斗限制和次数设置保留。

明确条件不满足时，跳到下一步且不增加成功次数；未知先等待，不假定可用。全部步骤被策略排除时有界停止尝试，保留运行意图，条件变化后可以恢复。非循环末项被排除时完成列表。已有精确起始的施法保留回执，不因策略变化改写或撤销计数身份；后续输入仍受实时策略检查。

请求、最终信号及读条末尾预留均检查对应步骤条件。魔杖和自动攻击状态确认仍保留，策略不满足不能通过开启确认推进。

结构化草稿保留策略、启用状态、施放类型、匹配身份与次数，拖拽、箭头、编辑、保存、方案切换及重新加载不把策略压缩为纯文本而丢失。保存策略使用列表配置保存流程并停止派发；不读取其他插件数据，不修改宏、绑定或输入路径。

## 实机验收

1. `/reload`，确认导航、派发总览、HUD及状态文字使用新称呼。
2. 为列表循环和优先级推荐各改一个不同方案名，选择使用该方案。观察页签当前标记与按钮，切换编辑其他方案确认标记仍指向实际使用方案；再次 `/reload` 确认名称保留。
3. 列表循环配置两个已学且已有直接按键的技能，为第一项增加使用策略“目标距离 20～30 码”。拖拽换序，再用箭头恢复，确认条件仍属于原技能。
4. 保存并关闭设置，在战斗中分别位于范围内外观察约 15 秒；范围外应跳过该项，范围内按配置次数及精确成功推进。
5. 为技能配置 CDM 或移动条件，观察约 30 秒。缺失或未知应等待；施法已经起手后条件变化不应丢失该次精确成功计数。
6. 再次保存、切换方案及 `/reload`，确认条件保留。测试结束使用 `/reload` 或退出游戏落盘，再检查本插件数据。
