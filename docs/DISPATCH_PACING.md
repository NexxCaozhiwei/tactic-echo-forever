# 起手确认与派发接续

日期：2026-10-26。版本保持2.0.1。用户要求采用起手确认、末尾接续和失败重试，并提供可调参数。

## 行为

- 尚未确认起手时，沿用原请求、信号和TEK输入链；TEK继续执行采样、限频、手动输入及前台检查。插件不根据请求数量推断游戏已接受输入。
- 精确公开的`SENT`或`START`确认本次起手后立即撤掉当前请求，发布零Token，保留起始身份和回执。即使读条信息尚未出现或法力已经扣除，也不重发旧技能、不清掉该次回执。
- 普通读条期间等待；仅在列表循环的合法末尾窗口，按照现有等级、策略、绑定、使用额度及实时条件复查，提出一个下一步排队尝试。
- 下一步为引导、切换类技能、未知类型、技能组，或条件不允许时，等待当前技能结束，不以旧技能连发填补空档。
- 下一步排队起手后停止重发。两次回执保持独立，必须先确认当前技能成功才能提升下一次身份；额外起始、失败或过期回执不能推进计数。
- 优先级推荐、技能组同样在起手后等待结果，但首版不新增它们的提前预测。引导期间保持事件锁和实时查询保护；魔杖、自动攻击及自动射击继续采用开启状态门禁。
- 当前精确尝试失败时保留运行意图与步骤，等待配置间隔后重新复查。只有精确成功才推进，重试等待不会被视为成功。

## 参数

在TEK设置页的“派发与接续参数”中调整。滑动步进0.05秒，也可手输范围内的小数。

| 参数 | 默认／范围 | 含义 |
| :--- | :--- | :--- |
| 读条末尾提前排队 | 保留原开关，缺省关闭 | 只授权既有列表循环普通读条的末尾排队尝试。 |
| 提前时间 | 保留原值；缺省0.20秒，0～0.50秒 | 0不提前；实际提前量不超过客户端公开`SpellQueueWindow`。用户已有0.25秒配置不会被改写。 |
| 失败重试间隔 | 0.15秒，0～0.50秒 | 从确认本次失败并撤销旧尝试后开始计算；0表示下一次既有心跳可重试，不代表无限派发。 |

参数修改会停止派发，需重新开启。无效输入保留并提示，不写入范围外值；按Enter及随后失焦只提交一次。设置打开时继续输出零Token。

重试间隔只控制已确认失败后的同一步重试，不等于TEK采样间隔、按键保持时间或普通技能间固定停顿。实际输入频率仍由TEK自身设置和安全门禁决定，本轮无需替换TEK程序。

## 身份与未知边界

重试等待属于运行态，不写入持久化运行意图；绑定到引擎、代次、索引和回执序号。停止、重置、编辑、重新加载或候选身份变化后不沿用旧等待。时钟受限时暂不派发，恢复公开后重新计时；时钟回退也重新计时。

本轮不查询GCD，不增加定时器、钩子或输入路径，不取消游戏已经接受的队列。零Token屏障可以撤销后续输出，不能证明跨进程中已经开始的单次输入已被撤回。

3. 另用两个已确认普通读条技能验证提前排队，分别测试0、0.25、0.50秒；只按实际成功回执评估是否接续，不把排队请求当成功。
4. 在普通读条中移动或受到打断，观察是否留在同一步、经过配置缓冲后重试；再验证停止、目标变化、技能组和魔杖交接。
