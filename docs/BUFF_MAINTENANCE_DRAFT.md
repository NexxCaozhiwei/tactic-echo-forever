# 增益维护首版

本次为 1.1.0 基线之后的功能修改，不提升版本。新增独立的“增益维护”页面，每个职业保存一份列表，不与列表循环或优先级推荐的三个方案绑定。

## 配置与优先级

2026-10-14 的未发布界面调整：共享策略中的“自身范围内可见敌人数”半径改为固定选择 5、10、20、25、30、35、40 码内，不再手输任意半径。旧半径保留原判断并提示重新选档；档位存在不代表探针已在当前客户端逐项实测有效。

支持拖入技能、精确 ID 新增、拖拽和箭头排序，以及右侧“编辑策略”。复用现有使用／跳过策略：所有使用条件必须满足，任一跳过策略满足则跳过；未知条件不授权施放。最多 16 个增益技能，同一精确 ID 不得重复。

首次载入时，从原有两种来源的三个方案提取已登记的增益，去重并保留策略；没有策略时增加“CDM 增益未活动”。原配置保留，启用维护后由维护列表接管这些技能，普通来源不重复推荐；关闭维护可恢复原配置行为。已保存维护列表不会在重载时反复迁移。

增益类型必须由已登记的自身／友方增益技能，或其他职业公开的 CDM 增益目录精确身份确认。治疗、伤害、造物、位移不能直接加入。类型确认不代替已学等级、资源、目标、范围、策略或输入门禁。

## 派发行为

维护优先于列表循环和优先级推荐。已有施法回执或排队时等待其结束，不为补增益打断当前技能。维护完成后恢复原列表位置和次数；精确成功只记在维护技能上。

脱战也可维护，但必须手动开启派发并确认公开脱战状态。自动进入世界不会授予脱战输入资格；停止、编辑、重载和世界切换清除该授权。脱战只允许维护增益，普通战斗技能保持待命。战斗来源为空时也可单独开启维护。

默认 CDM 条件表示公开界面的增益活动信号，不代表直接读取光环真值。目录 ID 与施放 ID 不同时，应在策略中选择实际增益目录 ID；缺失、隐藏、冲突或受限数据均保持未知。成功后抑制同一满足状态的重复补放，条件明确不满足后重新满足才再次维护；没有条件的技能每次手动开启最多维护一次。

## 本地验证与游戏验收

2026-10-14：新增模拟覆盖脱战手动授权、自动进入世界拒绝脱战派发、恢复列表位置及次数、停止撤销、独立保存与重载、拒绝伤害技能、未知 CDM 阻断、空战斗列表、已有施法保护、首次迁移与重复来源过滤。离线模拟不证明游戏施放成功。

提交前检查通过：独立契约、300 项运行模拟、164 项 APL 模拟、235 项 Python 测试及 17 项子测试、229 项 TEK 单元测试、2 项插件工具模拟、Python 编译、47 个 Lua 文件的 Lua 5.1 语法及中文文档检查。插件已部署至本地游戏目录，42 个安装文件与源码哈希一致；实际游戏验收仍未确认。

1. `/reload`，打开增益维护，加入当前已学并放在有按键动作栏上的霜甲术、奥术智慧；核对默认策略里的 CDM 增益目录 ID。保存并启用维护。
2. 关闭设置，保持脱战，先确认停止派发时约 10 秒不自动补放，再手动开启；观察约 30 秒，已有增益不重复施放，缺失且条件公开满足时按顺序补放。
3. 列表循环设置寒冰箭两次、火球术一次，进入战斗；第一发寒冰箭后让增益缺失，观察维护等待当前读条成功后补放，随后恢复第二发寒冰箭，不丢失次数。
4. 分别检查停止派发、切换到优先级推荐、CDM 未知及重载后的行为。测试结束 `/reload` 或退出游戏落盘，使用本插件 `TEF_DB` 核对日志。


## 2026-10-19：取消增益后不重补的复查

只读落盘会话69确认手动开启后，施放ID1460与7301各有精确成功回执；这只能证明当时补放成功，不能证明后续自动维护。用户进一步确认问题发生在手动开启后取消或失去增益。现有旧日志在维护待命时没有记录各行条件，不能据此确定全部现场原因。

离线复现了一条确定的漏补路径：成功后设置去重标记，读条或设置锁定期间维护直接返回，错过增益活动使条件变为不满足的阶段；随后增益取消，条件再次满足，但成功标记仍在。该逻辑在本轮审查整改前已经存在，新增回归此前未覆盖。

修复为复用既有维护采样节拍，在锁定期间也观察公开条件并更新去重标记；推荐替换、恢复原列表和派发仍等待锁定解除。维护待命及锁定的条件结果使用独立指纹去重记录，不覆盖战斗来源追踪；记录等待重新触发、CDM缺失或受限的原因。没有新增计时器、钩子、输入路径或脱战授权。

回归覆盖施放精确ID7301与观察目录ID168不同、普通取消重补、读条期间状态变化、设置期间状态变化、重复成功去重、原列表次数保留、未知及缺失阻断、诊断清洗和相同状态不重复记日志。离线通过不等于现场问题已全部确认解决。
