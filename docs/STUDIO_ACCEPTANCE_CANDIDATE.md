# Studio整合验收候选

日期：2026-10-16。基于 `361e439` 及第一、二阶段开发结果，版本号仍为 `1.3.1`。这是同一工作区的整合开发包，不表示已发布新版本或已通过游戏实测。

## 一、本轮结果

原先分离的主列表、策略侧窗和技能组列表已接入同一Studio工作区。主列表独立滚动，不再嵌套在旧设置整页滚动容器中；保存与诊断区域固定在列表下方。策略表单成为Inspector的内容，技能组步骤在同一个主编辑区展示。

本轮覆盖原规划第三至第五阶段的主要编辑流程，并修复过渡界面中的选中身份、排序重绑、删除回调、窄屏遮罩和低窗口高度问题。不同客户端下的最终字体、材质、拖放和交互手感仍需要实机验收。

## 三、编辑与保存

| 项目 | 已实现行为 |
| :--- | :--- |
| 工作区 | 切换来源页和三套编辑方案；方案名称、正在编辑、正在使用、启用状态和草稿星号分别显示。 |
| 主列表 | 两种父列表及组内步骤使用统一技能行；保留精确ID、次数、使用策略、不可用跳过、上下移动、拖放、删除和撤销。 |
| 复制 | 深拷贝选中技能或技能组到下一行，保留策略；仍受父列表16项、组内8步限制。 |
| Inspector | 点击条目直接绑定原策略表单，不再要求打开独立策略窗口；数值校验失败阻止切换，原输入保留。 |
| 条件 | 复用原定义，可搜索名称、字段名和分类；保留职业限制。界面显示“满足时／除非”，底层仍是 `use／skip`。 |
| 条件摘要 | 主列表最多显示三个条件摘要，更多条件显示数量及完整提示；摘要表示要求，不表示条件已满足。 |
| 条件顺序 | 上下按钮调整同一策略内的显示顺序；仍按原有全部满足逻辑求值，不增加新的逻辑操作符。 |
| 技能组 | 左侧保持组内列表可见，右侧切换组属性或某一步的策略。返回父列表先校验并暂存，显式保存才持久化；空组不能当作已保存组返回。 |
| 方案属性 | 在Inspector编辑名称、启用、使用方案和循环方式。名称使用单独的“保存名称”，列表使用“保存方案”；不把切换编辑误当运行来源切换。 |

列表循环保存继续走 `Profiles:Save`，APL保存走 `APL.Custom:Save`，维护保存走 `Maintenance:Save`，组编辑走原 `SaveSkillGroup`。没有第二套持久化路径。

次数、使用策略和不可用跳过保留行内快速操作，没有为了迁移外观移除现有入口。技能组的保持条件、退出方式和父项策略通过父列表组行的Inspector编辑；组轮数及名称通过组属性编辑。

切页及关闭继续使用原提交、会话草稿与确认机制；关闭不是自动保存，重载前必须显式保存。打开Studio继续保留运行意图并阻断输入，标题栏启停只调用Runtime接口。

## 四、技能库

技能库按需读取公开法术书，最多16个技能页、每页256项、总扫描预算2048槽位；只收录公开精确ID、公开非被动且公开确认已学的条目。不能确认的身份被排除并提示存在未知项，不按技能名称、最大ID或静态职业目录推断等级。

支持中文名称、字段中的精确ID搜索、分页、刷新、点击追加和拖入某行之前。新增时重新检查精确已学及被动状态，失败保留原列表。不同已学等级即使同名也保留各自精确ID。

普通刷新复用技能库缓存，不逐帧扫描法术书。学习新技能后可点击刷新；不保证游戏事件发生后自动重扫。已有技能／宏光标仍走原 `ActionSources:Cursor` 身份核对，技能库不会创建或修改宏、动作栏或按键。

## 五、Trace、问题及状态

底部提供 `APL TRACE`、问题及输出三个标签。

- “只读采样”针对当前草稿建立界面专属快照，通过原 `Sample` 和 `Check` 解释结果；不调用候选替换，不写运行快照、不推进序列、不重新武装额度。
- 可手动打开“实时”模式，复用既有界面心跳，最多每0.20秒采样一次；输入框有焦点、焦点未知、设置关闭或时间未知时暂停自动采样。
- Trace记录采样时间、精确技能ID、三值结果和原因。点击定位前校验引擎、来源、方案、代次、回执、采样修订及整份草稿内容；不匹配时要求重新采样。
- 采样与求值前后分别检查身份；期间发生状态或草稿变化则拒绝发布结果。
- 问题页复用 `Custom:Audit`，只列出能够证明的矛盾及原有提示，不虚构不可达证明。输出页显示原有界事件时间线。
- 技能行只在对应公开采样足够新鲜时显示诊断性的 `READY` 或 `BLOCKED`；没有样本、样本失效或未知时保留 `UNKNOWN`，停用为 `DISABLED`。没有把草稿预览伪装成实际运行的 `ACTIVE`。
- TEAP开关不表示桌面端连接成功，状态栏仍明确写“TEK连接：未确认”。

Trace和主列表的状态均不能授予输入资格。显示“条件符合”不保证目标、按键、战斗门禁或真实施法成功；真实推进仍只认原回执链路。

## 六、布局及性能

窗口宽度最多1560、高度最多920逻辑单位。宽度不足时先折叠工作区；Inspector无法并排时覆盖编辑区，并使用遮罩阻止点击穿透，提供收起入口。折叠的工作区和技能库可从活动栏打开。

主列表、Inspector、技能库及方案属性各自使用明确的滚动区域；主列表与整页滚动不再叠套。低窗口高度下诊断区变为紧凑展示，点击底部标签可在剩余空间内展开；完整Trace行在足够高度时展示，极低窗口不声明完整体验。

父列表仍各预建16行，组内8行，技能库8个可见行，Trace16行；条件表单复用原池。普通状态更新不重建完整界面，没有新增定时器或钩子。模拟预热后25次Inspector切换与诊断刷新不新增Frame，表单同步注册数量保持稳定。

已进行真实Lua控件坐标的离线捕获与模拟绘制，检查列表和固定保存区、Inspector视口、遮罩及工具栏位置。此模拟图不是游戏截图，不能证明客户端字体、纹理、原生滚动或鼠标事件已经通过。

## 八、本次需要用户进行的整体验收

本轮不要求区分旧面板和新面板的问题，按下列连续流程记录体验即可。以下目前均为“未测”：

1. 游戏内 `/reload` 后运行 `/tefui`，检查标题、活动栏、主列表、Inspector和底部保存区域有无遮挡；拖动窗口，改变游戏窗口或UI缩放后再检查。
2. 打开技能库，搜索寒冰箭或精确ID，追加到优先级列表，再拖到某行之前；取消一次拖动，确认顺序保持。
3. 点击技能行，在右侧增加范围条件，尝试错误数值并切换条目，确认错误输入保留；修正后保存，关闭重开并重载核对。
4. 切换列表循环，新增火球，设置3次及每目标一次；排序后检查右侧仍对应选中的技能，保存后核对次数与顺序。
5. 创建技能组，加入两个技能，设置3轮；选择组内技能编辑策略、排序，再返回父列表和保存，确认组名、轮数及策略保持。
6. 复制、删除和撤销一条规则，确认复制的条件互不联动，撤销后条件仍在；切换三个编辑方案，确认草稿星号与正在使用标记区别清楚。
7. 点击只读采样，查看Trace；调整顺序后确认旧Trace不能跳转到错误条目。打开实时模式，在输入框输入时确认不会自动改写输入。
8. 缩窄窗口，确认工作区能打开、Inspector覆盖时不能点穿，收起后列表恢复可操作；低窗口下方案属性、保存和取消仍能到达。

界面验收完成后，再单独检查普通战斗、引导、固定序列5019交接、维护插入及精确回执等真实派发场景。离线回归、模拟图和部署哈希不能代替这些检查。

## 十、用户反馈后的代码修正（未部署）

用户报告列表循环、增益与紧急页存在严重遮挡，技能库分页与滚动冲突、缺少等级、切页不关闭，以及重复导航和无效方案属性入口。本节记录后续代码状态，前文部署包与实测状态属于上一轮，不能用于证明本节已经部署或实机通过。

- 取消仅凭几何签名跳过布局的处理；即使尺寸相同，每次刷新仍隐藏旧页面及非当前来源的列表、工具栏和保存区。
- 技能库改为右侧独立弹窗，标题区域可拖动且限制在屏幕内；删除上下页按钮，使用单一虚拟行偏移驱动滚轮和滑块。窗口高度不足时减少显示行数。
- 技能等级只读取当前法术书槽位的公开等级数字或同名等级文本；冲突、缺失或受保护时显示“等级未知”。等级仅用于展示，不授予新技能资格。
- 成功切页关闭技能库、清理焦点和拖动；输入校验阻止切页时保留当前页面。
- 工作区删除重复的“派发设置”。“方案设置”用于改名、启用、切换使用及列表循环选项；维护页只显示有效的维护启用操作，不显示战斗方案标签、改名或使用按钮。
- 增加4项回归，覆盖重复布局可见性、滚轮与滑块共用偏移、切页与导航、公开等级及冲突。

本轮没有部署、重新打包、提交或推送。游戏中需复核两个问题页面的滚动列表、保存区与Inspector遮挡，以及技能库右侧位置、拖动、滚动和等级文本。本轮离线检查不代表上述实机项目通过。

离线验证记录：主Lua模拟301项、APL及关联模拟305项、Python回归235项及17个子测试、TEK单测229项、插件交付单测2项均通过；独立基线检查、Python编译、56个Lua文件的5.1语法检查及162份中文Markdown扫描通过。列表循环和维护页的离线坐标示意检查未见旧页面覆盖主列表；它不是游戏截图，不证明游戏内字体、滚动和层级已通过。

## 十一、2.0.0视觉修正

用户在上一轮部署后反馈主布局无明显问题，并指出“持续参与推荐”末尾缺字和选中技能行边框不持续高亮。2.0.0使用兼容字体的下拉标记，移除选择项对特殊圆点的依赖；三类技能行的选中状态统一参与边框绘制，鼠标移出与普通刷新不再覆盖。Studio面板和技能行采用原生圆角边框。增加2项回归，分别覆盖三类技能行的持续高亮与紧凑下拉文本。

当前基线已推进至2.0.0；前文的1.3.1包、部署及未部署记录是历史步骤。本轮视觉修正需在游戏内复核，真实派发验收状态不因版本推进改变。
