# TEF UI/UX 开发与验收标准

制定日期：2026-10-15。标准版本：1。适用于游戏内设置窗口、列表循环、优先级推荐、增益维护、技能组、条件编辑、确认弹窗和HUD；桌面TEK可参考视觉与文案规则，输入和前台门禁仍遵循其独立契约。

本文件是后续界面开发、代码自查和游戏内验收的依据。它规定目标行为，不表示当前1.2.1已经全部满足。仅新增规范文档不提升插件版本，也不授予提交、推送或部署权限。

## 一、规范依据与适用边界

采用通用可访问性规范的可辨识、可操作、错误反馈原则，并参考桌面界面关于层级、分组、对齐和按钮表达的指导。以下数值分为行业依据与本项目约定，不能把项目约定写成行业强制要求。

| 依据 | 采用内容 | 在TEF中的适配 |
| :--- | :--- | :--- |
| [文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 普通文字最低4.5:1；符合其大字定义的文字最低3:1。 | TEF设置界面统一要求文字至少4.5:1，不将游戏字体大小直接换算成网页大字豁免。 |
| [非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) | 识别控件及状态所必需的非文字视觉信息，与相邻颜色至少3:1。 | 检查必要的边界、焦点和状态标记；装饰线不承担唯一识别职责。 |
| [指针目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 网页指针目标一般至少24×24 CSS像素，规范另有例外。 | 作为目标易点击的参考；本项目默认32单位高，并在最终屏幕渲染中检查缩放后的点击区域。WoW单位不等同CSS像素。 |
| [桌面内容布局与间距指导](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics) | 用层级、间距与一致的对齐组织内容。 | 本项目采用4单位基础网格、统一列宽与间距，具体值见后文。 |
| [桌面按钮指导](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/buttons) | 按钮清楚表达操作，并按用途选择合适的交互形式。 | 使用明确中文动词，区分保存、暂存、使用方案、清空及关闭。 |
| [焦点外观说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance) | 为键盘焦点提供容易辨认的外观；此项属于增强级别要求。 | TEF主动采用明显焦点框作为项目要求，不据此声称整个插件达到该认证级别。 |

网页标准在此作为设计参考，不声称WoW插件获得完整WCAG符合性认证。字体、鼠标与键盘能力须在目标客户端核实；不为满足网页条款引入游戏不支持的交互或全局按键拦截。

执行优先级：用户明确要求及AGENTS.md运行契约优先；本文件中的“必须”是界面验收门槛，“建议”是默认设计选择。例外须记录理由、范围和替代方案，不能把未知或未测试改写成通过。

## 二、设计原则与信息结构

1. 战斗中快速识别当前技能、运行状态与阻断原因；复杂编辑集中在设置窗口。
2. 每个页面围绕一项任务组织，顺序为页面标题、当前对象或方案、编辑内容、反馈、操作区。
3. 列表和详情明确区分。技能名称、精确ID、条件和运行来源不得混在一段长文本中。
4. 常用功能直接可见；高级诊断按需展开。关键状态和阻断原因不能只放在Tooltip中。
5. 所有页面使用同一套字体、间距、颜色和按钮语义。减少无意义的边框、重复标题和长说明。
6. 显示“正在使用”的方案与“正在编辑”的方案必须分别标明，避免用户误以为切换编辑页就切换了运行方案。
7. 设置打开时，必须明确说明当前派发受设置门禁阻断；是否保留运行意图按Runtime实际状态显示。

## 三、尺寸单位、网格与设计变量

本文件的“单位”指布局参考尺寸下的WoW UI逻辑单位。设计值应集中定义为主题变量；允许固定的标准控件尺寸，但不得用散落的屏幕绝对坐标定位整个界面。最终尺寸受UIParent、插件缩放和客户端字体渲染影响，以实机显示为验收依据。

| 项目 | 项目默认值 | 使用要求 |
| :--- | :--- | :--- |
| 基础网格 | 4 | 新增尺寸和间距优先取4的倍数。 |
| 页面外边距 | 24 | 小屏可降至16，不压缩到贴边。 |
| 卡片内边距 | 16 | 同一页面卡片保持一致。 |
| 控件水平间距 | 8 | 图标与文字、同行按钮的默认间距。 |
| 字段垂直间距 | 12 | 计算已包含错误提示所需空间，不能让错误覆盖下一行。 |
| 分组间距 | 24 | 分隔不同任务；优先留白，必要时加标题或分隔线。 |
| 标签到输入框 | 8 | 标签在输入框上方或固定左列，两种形式不得随机混用。 |
| 普通控件高度 | 32 | 按钮、输入框和选择项同高。 |
| 紧凑列表控件高度 | 28 | 仅用于密集列表；缩放后须检查可读性和点击区域。 |
| 常用文字按钮宽度 | 96或120 | 随标签长度增加，不为塞入一行而缩小字体。 |
| 数值输入框宽度 | 72或96 | 上下限同行使用相同宽度。 |
| 精确技能ID输入框宽度 | 至少112 | 完整显示合法ID，左右各留至少8单位内边距。 |
| 名称输入框宽度 | 至少240，随容器伸展 | 不以宽度决定存储上限；长输入可横向滚动。 |
| 列表行最小高度 | 40 | 有两行信息时至少64，并随内容增加。 |
| 操作区高度 | 至少56 | 与滚动内容分离，保存、关闭始终可达。 |

建议集中使用 `fontBody`、`controlHeight`、`spaceInline`、`spaceSection`、`colorText`、`colorFocus` 等主题字段。命名遵循现有Lua模块风格；本规范不要求一次性重命名全部历史代码。

## 四、字体与文字层级

| 内容 | 参考字号 | 排版要求 |
| :--- | :--- | :--- |
| 窗口主标题 | 20 | 单行、左对齐，避免全大写装饰或整句彩色。 |
| 页面标题 | 18 | 与内容左边界对齐。 |
| 分组标题 | 16 | 与正文有明确层级，标题下留8单位。 |
| 正文、字段标签、输入内容 | 14 | 同一表单使用一致字号。 |
| 按钮、选择项 | 14 | 文字垂直居中；紧凑列表允许12。 |
| 辅助说明、单位、次要ID | 12 | 不用于关键阻断、错误或主要操作。 |
| HUD技能名称及关键状态 | 默认16，可配置 | 用户可调节；采用独立HUD主题，不跟随设置窗口自动缩放。 |

必须使用客户端提供且具有简体中文字形的字体，优先沿用公开的游戏字体对象或字体路径。没有单独需求不新增外部字体依赖。精确ID、次数、百分比等保持清晰，可采用等宽数字的视觉对齐，但不能假定客户端一定存在等宽中文字体。

设置窗口自动缩放后，关键文字不得因缩小到难以辨认而继续强行完整展示。应优先改为覆盖布局、增加滚动或拆分内容。正常参考尺寸下，关键正文不低于14，辅助文字不低于12；实机缩放后需重新判断实际可读性。

段落左对齐，不使用两端分散对齐。建议行高为字号的1.4～1.6倍，段间距为8～12单位；在WoW中按实际字体高度和换行结果调整，不强行套用网页行高。辅助说明优先控制在两行；长说明放到展开区或Tooltip，错误和关键限制仍须可见。

长技能名称或方案名称只能在列表概要中省略，提供完整名称的Tooltip；编辑框和确认弹窗保留完整内容。不得按字节直接截断UTF-8字符。多个不同名称截断后相同时，须补充ID或其他公开身份区分。

## 五、颜色、图标与状态

采用深色不透明或接近不透明的设置背景，降低游戏场景对文字的干扰。颜色仅表达语义，不能是唯一的信息载体。

| 语义 | 建议颜色 | 必须伴随的信息 |
| :--- | :--- | :--- |
| 背景与面板 | 深蓝灰 | 清楚的层级和留白，避免多层相似边框。 |
| 主文字 | 接近白色 | 所有背景上至少4.5:1。 |
| 次要文字 | 浅灰蓝 | 同样检查文字对比度，不以整体低透明度代替设计。 |
| 当前选择或正在使用 | 青绿 | 选中标记及“当前”“正在使用”等文字。 |
| 键盘焦点 | 明亮蓝色或青色 | 清楚的连续轮廓，与选中状态有区别。 |
| 成功 | 绿色 | “已保存”“已暂存”等精确文字。 |
| 警告与未知 | 琥珀色 | “未知，暂不派发”等原因文字。 |
| 错误或破坏性操作 | 红色 | 明确错误或操作对象；不只使用红边。 |
| 不可操作 | 降低强调度 | 仍可读的名称、禁用原因和恢复条件。 |

依赖边框识别输入框或按钮时，该必要边框须满足非文字对比度目标；装饰线不必全部做成高对比。焦点框建议至少2单位厚，并在缩放后检查连续清晰的轮廓。普通悬停、按下、选中、禁用和焦点状态应分别定义，不让鼠标离开时覆盖选中状态。

对比度按最终组合背景计算，涉及透明度时先合成背景。建议使用固定配色进行计算，再在明亮与黑暗游戏场景截图复核。不得用“看起来明显”代替测量。

技能图标建议32×32；表格紧凑图标允许24×24。图标与技能名称、精确ID保持对应，未知图标使用占位。仅有图标的按钮必须有中文Tooltip，并保证足够的点击面积。

## 六、对齐、锚点与窗口适配

- 主设置窗口相对UIParent定位，并限制在可见区域。编辑器相对主窗口或可用内容容器定位，不使用某个分辨率的屏幕坐标。
- 使用统一内容左边界；标题、说明、输入框和列表按列对齐。同行控件按垂直中心对齐，文字标签尽量按基线对齐。
- 文字默认左对齐，按钮标题居中；表格中的数字可右对齐。ID与名称分列，避免用空格模拟对齐。
- 布局计算须考虑父容器尺寸、有效缩放、外边距、滚动条和弹出菜单宽度；不得只检查主窗口宽度。
- 有足够空间时主列表与编辑器并排；不足时采用覆盖详情或单列布局，并提供明确返回或关闭入口。
- 覆盖详情必须拦截背景点击，防止点击穿透。模态确认必须高于编辑器和菜单，并阻断底层操作。
- 不得无限缩小窗口来容纳全部内容。若无法同时保持可读文字与可用尺寸，使用滚动、分组折叠或单列布局。
- 窗口位置在同一布局模式下应保持稳定；尺寸改变、恢复默认或窗口越界时才纠正位置。窗口缩放或位置变化不得修改策略内容。
- 标题和底部操作区保持可达；只让内容区域滚动。避免两个同方向滚动区域叠在一起而没有明确边界。
- Tooltip和条件菜单不得出屏幕。空间不足时自动换侧或向上展开；不得覆盖当前正在输入的值。
- 同一页面不能既用父级缩放又逐控件叠加缩放补偿，导致字号和点击区域不一致。

## 七、文本框、数值与滑块

每个输入框必须具有持续可见的标签。示例或占位说明不能替代标签。范围、单位和空白语义放在字段附近，例如“距离下限（码）”“上限留空表示不限”。

数值输入显示合法范围并区分整数、小数与可留空。必须保留 `0`、空白、未知三种语义；不把无效输入自动变成0，也不把 `UNKNOWN` 当作满足条件。公开数值与Secret的处理仍须先经过Safety。

输入校验分为格式、范围与业务关系三层。例如：下限必须是数值、处于合法范围，且不得高于上限。错误提示应指明字段和修正方式：“距离下限不能大于上限”，而非只有“保存失败”。技术原因码保留在诊断中。

用户输入期间不覆盖正在编辑的内容。刷新其他控件、改变跳过开关、排序或打开详情前，必须先收集当前输入；校验失败时保持草稿和编辑位置。可逆的输入错误优先保留原文本供修正；确需恢复上次合法值时，必须提示已恢复什么值。

Enter提交当前字段或当前表单，提交必须幂等；失焦不得再次执行同一次写入。Escape取消当前输入或当前弹窗，不写入无效值。不得为了处理Escape新增全局游戏按键拦截；必须核实当前客户端的焦点能力与既有快捷键兼容性。

支持复制、粘贴和常规光标编辑。允许前后空白的字段统一去除边缘空白；名称中的合法空格保留。文本上限按真实存储契约校验；技能组名称目前是1～64字节，界面须明确标注，不能谎称支持64个中文字符。

滑块用于连续或有限范围调整；精确值同时提供数字显示，确有精确输入需求时提供输入框。拖动不改变范围外的数据，不反复保存全配置或重建整页。拖动到同一个值不重复提交；滑块有效操作后清除已经解决的错误提示。

## 八、按钮、选择项与Tooltip

按钮名称使用具体动词，优先“保存方案”“清空条件”“更换技能”“返回技能组”。上下文不足时不用“确定”“应用”或“操作”代替具体行为。图标排序按钮允许保留“↑”“↓”，Tooltip说明移动方向及对象。

每个操作区只有一个默认主要操作，次要操作弱化显示，破坏性操作与保存保持至少16单位间距。关闭按钮位于窗口右上角；主保存操作位于内容底部操作区右侧，取消或返回位于其左侧。列表内的排序和删除位置在所有行保持一致，不因名称长短变化。

1.2.1及更早界面的保存按钮主要在左侧；1.2.2将主方案、策略及技能组保存移到固定底部右侧。其他新增页面同样采用该顺序。

按钮状态至少包括普通、悬停、按下、焦点和禁用；可选择控件还包括选中。禁用按钮必须阻止回调，同时提供原因与恢复方式；若原生禁用状态不能接收悬停，使用相邻说明或不会触发操作的提示区域。

布尔设置用开关；互斥的少量选项用分段选择；选项过多或文字较长时用菜单或分组列表。不得为把七个以上长选项塞入一行而缩小文字或让标签换成无法理解的缩写。

常见术语统一：“启用方案”表示获得被选用资格，“使用本方案”表示切换运行来源，“开始／停止”表示运行意图，“暂停／继续”表示可恢复的暂停，“保存”表示持久化，“暂存”表示仅更新草稿。文案必须对应实际代码行为。

Tooltip覆盖含义不明显、图标、截断名称、禁用状态和高级条件。内容依次为名称、用途、限制或生效时机，默认最多三段。OnLeave、控件隐藏、复用或菜单关闭时清理该控件拥有的Tooltip；不得无条件隐藏其他插件正在显示的提示。

## 九、草稿、保存、删除与反馈

必须明确区分“正在编辑”“已暂存，尚未保存”“已保存”“正在使用”。进入设置不等于开始运行；显示成功消息也不等于游戏施法成功。

同一编辑流程使用一致的草稿语义：切换详情收集输入并保留草稿，不隐式保存整个父列表；显式保存才持久化。退出或切换会丢弃修改时，必须提供“保留编辑／放弃修改”的明确选择。已有运行意图的清除和设置门禁继续按AGENTS.md及Runtime契约执行。

保存前校验全部相关字段，失败时不得部分持久化。成功后说明保存范围及派发影响，例如“技能组及所属方案已保存，原派发已停止”。失败时保留草稿并指出可修正原因，不能显示成功色。

清空整个方案、全部条件、整组步骤和恢复默认必须确认，弹窗写明对象、范围和是否需另行保存。普通单条删除优先提供撤销；不能撤销且删除的是含多步骤的组时必须确认。不要求每次移动或开关都弹窗。

确认弹窗须有清楚标题、对象和具体按钮：“清空条件／取消”“放弃修改／继续编辑”。默认焦点偏向保留数据；Escape取消。弹窗存在时底层列表、保存和切换不可操作。战斗或设置关闭等状态变化不得留下孤立遮罩。

反馈位置稳定：字段错误紧邻字段，页面保存状态固定在操作区上方，运行阻断显示在HUD或运行总览。字段错误持续至修正或主动取消；普通刷新不得覆盖。成功状态可由下一次操作替换；不为自动消失另建定时器。

## 十、列表、技能组与条件编辑

- 使用稳定的列顺序：序号与技能身份、次数或组信息、条件编辑、排序、删除。列表头或局部说明解释计数语义。
- 每步每轮、每个目标、每次战斗等限制必须以实际支持的行为呈现；不显示尚未实现的选项，不把未知目标身份当作新的目标次数。
- 技能组父项显示组名、步骤数和轮数；组内展示每一步的精确技能及次数，不把父项技能图标误当整个组的运行资格。
- 更换技能保留条件时，须提示显式观察ID仍指向原观察对象；未知等级不自动升级技能。
- 条件编辑明确显示“全部满足”和“任意跳过策略满足”的逻辑，不能用视觉相邻暗示不同逻辑。
- 范围条件使用“下限～上限，含边界”等清楚文本；旧档位保留但不支持时标明需调整。
- 职业专属条件仅向对应职业开放。加载历史不支持配置时，显示解释并提供删除或替换，保留未知阻断。
- 空列表显示用途及下一步操作，例如“尚未添加技能，可拖入技能或输入精确ID”；达到上限时说明上限并禁用添加。
- 拖入、插入和替换必须区分，提供明确落点；拖入失败保持光标与原列表，给出原因。保留ID输入和按钮作为拖拽的替代操作。

## 十一、HUD与战斗场景

HUD优先展示当前推荐技能、运行或阻断状态、必要进度；其次才是预览和诊断。高频变化的文本不得导致整体宽度不断跳动。没有推荐时显示原因，不显示上一次技能为当前可释放。

HUD位置、字号和缩放独立配置；调整HUD外观不得改变技能资格、目标、运行意图或绑定。隐藏HUD只改变显示。关键状态必须在灰度或色觉差异下仍能靠文字辨认。

没有单独需求不增加闪烁、循环动画、音效或战斗中模态弹窗。未知状态用稳定文本表示，不通过不停变色制造“正在恢复”的假象。允许在现有Tooltip中展开技术诊断。

## 十二、实现规范与性能

使用现有Frame、Text、按钮、输入框和选择控件构造函数；相同语义共用主题变量与状态绘制函数。页面布局与运行判断分离，UI不直接请求输入，不新增派发路径、定时器或钩子。

刷新分为状态同步、内容更新和结构重建。只有条目或条件结构变化才重建表单；普通状态变化不重扫法术书、天赋或全部姓名板。复用既有心跳和脏更新机制；不在新增OnUpdate中运行完整扫描。

Frame不能靠Hide作为资源销毁方案。可变表单采用复用池，并在复用前解除旧回调、焦点、Tooltip归属和同步注册，重置选中、禁用、父对象和锚点。池大小受支持的最大表单规模约束；更换条目后回调不得仍指向旧技能。

隐藏页面检查包含父级可见性，不能只检查控件自身IsShown。回到页面时重新同步，避免隐藏期间的优化导致陈旧状态。编辑中的输入框不被常规同步覆盖。

日志保留既有事件与原因码，用户界面显示中文原因及可执行下一步。注释描述必要的行为或约束；不添加与实现重复的长注释，不仅为了命名统一进行大规模重构。

## 十三、验收矩阵与完成定义

建议实机覆盖以下组合，分辨率为物理窗口或屏幕尺寸；记录实际UIParent尺寸和缩放，不能把物理分辨率当作逻辑尺寸。

| 场景 | 必查项目 |
| :--- | :--- |
| 1280×720或可达到的较小窗口 | 单列或覆盖布局、字号可读、底部操作可达、菜单不越界。 |
| 1920×1080 | 默认布局、列对齐、并排编辑、弹窗和Tooltip。 |
| 2560×1440 | 字体清晰、缩放一致、窗口定位稳定。 |
| 3840×2160（具备环境时） | 高分辨率与不同游戏缩放；未测试必须注明。 |
| 客户端允许的低、中、高UI缩放 | 点击区域、焦点框、文字换行、滚动边界。 |
| 长中文名、长ID、空列表、满列表和最大条件表单 | 截断说明、行高、结构复用和上限提示。 |
| 已知真、已知假、UNKNOWN及Secret | 文案准确、无格式化错误、未知始终阻断。 |
| 保存失败、输入错误、清空取消、退出取消 | 草稿保留、错误持续、无误保存、无孤立遮罩。 |
| 进入战斗、停止、暂停、恢复与reload | 输入门禁、焦点释放、显示与运行状态一致。 |

每次涉及界面的交付，逐项记录以下清单；使用“通过／失败／未测／不适用”，不只写“已检查”。

- 字体层级、中文字符和数字完整；长文本有明确处理。
- 同行对齐、边距和间距统一；无文字、边框或控件重叠。
- 文字对比度及必要控件状态达到目标，状态可通过文字辨认。
- 全部操作在目标窗口尺寸可达，覆盖编辑与弹窗无点击穿透。
- 输入不丢失；Enter与失焦不重复提交；错误不被普通刷新覆盖。
- 保存范围、生效时机、暂存与运行方案表达一致。
- 删除、清空与退出有适当保护；取消后数据保持。
- Tooltip、菜单与焦点及时清理；现有游戏快捷键不被意外拦截。
- 表单预热后，重复打开、关闭和重建25次不新增同规模Frame；同步注册不持续增加。
- 最大支持表单仍可滚动，回调身份正确，隐藏页不进行无必要同步。
- README要求的检查、Lua 5.1语法、中文Markdown与差异检查完成；实机结论单独记录。

界面完成至少需要代码回归和相关实机验收。模拟通过只证明受测代码逻辑，截图只证明该尺寸下的视觉结果，部署哈希只证明文件一致；三者不能互相代替。

## 十四、当前差距与后续采用方式

1.2.2已完成统一字体与32高控件、固定底部保存、条件持续标签及原子校验、局部焦点边框、删除撤销／确认、跨方案草稿保留和Tooltip归属清理。回归覆盖最大表单连续重建25次、输入保留与取消等路径。

1.2.3进一步统一一级列表工具栏及行内按钮网格，按可用高度保留列表下沿；HUD采用三列数值控件、标签样式置顶，并新增整体距离文字样式。已有绑定覆盖功能已移除。1.2.4将列表循环／组内条目调整为80高两行、普通优先级条目44高，行内控件28高，四周至少8单位边距；常规表单仍保持32高。

仍需实机核验的项目：

- 默认配色的计算结果须与实际游戏透明背景、字体和截图对照；用户自定义HUD颜色不保证达到统一对比度。
- 窄于设计宽度时仍有最低85%的缩放，关键文字可读性和点击区域需测试；非常窄、非常短的窗口不声明完整适配。
- 下拉菜单、长技能名、最大表单和弹窗在不同分辨率及UI缩放下需检查越界、遮挡和滚动。
- 输入框局部焦点与弹窗Escape取消已有实现；全部自定义按钮的键盘遍历、原生快捷键兼容性未作完整实机认证。
- 普通页面关闭保留会话草稿，reload前必须保存。技能组未暂存退出使用放弃确认；不要把保留草稿的关闭误写成自动保存。

后续修改界面前先阅读本文件，明确涉及哪些条款；实现时使用统一控件，完成后对相关条款逐项验收。为遵循本规范需要改变运行语义时，先核对AGENTS.md及现有契约，不能借界面重构绕过门禁。
