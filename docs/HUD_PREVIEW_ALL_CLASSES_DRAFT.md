# HUD 候选预览与全职业自定义 APL 草稿

本改动纳入 1.1.0 基线，开发阶段使用 1.0.23 验证。

## 候选图标

有目标时，主图标保留当前推荐；后两个图标展示当前符合条件、优先级靠后的不同技能。不足三项时重复最后一项：只有 A 显示 AAA，只有 A、B 显示 ABB，有 A、B、C 显示 ABC。无目标时，自定义 APL 按当前方案中启用且配置合法的技能优先级展示；人工序列从当前步骤向后展示。

自定义 APL 使用规范化的条件采样进行预览筛选，未知不算符合条件。施法回执锁定期间，复用既有刷新入口每 0.20 秒读取预览快照；预览不能替换主推荐、运行意图、回执身份或创建派发请求。人工序列的候选过滤不推进计数或改变执行顺序。隐藏预览设置仍生效。

## 全职业技能支持

自定义 APL 配置、保存、来源选择和求值不再要求法师职业包。所有已登记职业均可使用三套独立自定义配置，内置法师模板继续单独保留。

技能使用用户配置的精确 ID，必须公开确认已学、可用、资源足够及相关射程。法师已有技能类型继续使用登记语义；其他技能通过公开有害、帮助和范围元数据确认目标类型。没有明确元数据时等待，并提示选择施放类型；不把未知当作自身技能。

策略窗口新增施放类型：自动、自身、友方、敌方、地面。友方技能仍遵循合法目标或公开开启的游戏自动自施法设置。地面技能只触发现有按键，用户操作落点；公开选点中或选点状态未知时阻断重复派发。被动技能不能派发；没有目标语义登记的技能还需公开确认非被动。技能 ID 缺失、受限或未学时不能授权。

该框架移除了职业与伤害技能白名单限制，不表示已经实测全部职业技能。物品使用不等同于已学法术，不通过技能 ID 路径自动授权。所有技能仍依赖既有动作栏、按键和输入链；不生成或修改宏、绑定、目标或落点。

## 本地验收与后续实测

新增模拟覆盖跨职业配置与通用主动技能派发、被动与未知阻断、目标类型覆盖、地面选点保护、ABC／ABB／AAA、无目标优先级、人工序列只读预览。

实机步骤：

1. `/reload` 后打开自定义 APL，确认新增施放类型可编辑，原有方案与策略保留。
2. 配置三个已学、有直接按键的技能，确认有目标时依次显示三个合格技能；让后续技能因条件或资源不满足，分别观察 ABC、ABB、AAA 各约 15 秒。
3. 清除目标，观察约 15 秒，确认按启用配置优先级显示；重新选目标，确认恢复条件筛选。
4. 使用另一职业角色，为一个已学主动技能创建简单使用策略，自动类型无法识别时明确选择施放类型。进入战斗观察约 30 秒，并确认成功回执推进仍正确。
5. 地面技能触发后观察选点期间是否停止重复按键，人工确认落点后检查成功记录。
6. 测试结束后 `/reload` 或退出游戏使日志落盘。界面观感、钩子、按键输入和全部职业技能兼容性仍须按实机证据确认。
