# TEF 1.0.16 — 固定序列手动起手接续

## 行为

自动模式、已启用的固定序列在公开脱战状态下保持回执监听。收到当前步骤精确技能的公开起始与成功身份后，按既有重复次数和步骤规则计数，与自动施放使用同一计数路径。例如 A→B→C→D 中手动成功施放 A，当前步骤转到 B；若 A 配置三次，则需三次独立成功后转到 B。

待命仍关闭连续派发、撤销请求并输出零 Token。请求入口阻止待命请求；最终信号在自动模式下也要求公开战斗状态为真。自定义 APL 脱战待命保持只读，不增加输入路径。

手动起手跨进战斗不恢复或暂停序列引擎，不更换既有回执代次。即使进战事件早于客户端公开读条，已关联的当前手动起始也阻止自动重复起手，直到该次成功或失败。

主动暂停、设置打开、重置、配置编辑、目标或世界切换及未知战斗状态的撤销保护保留。失败、重复、受限身份、缺少当前起始及非当前步骤技能不计数；沿用现有有界身份预算。

## 离线验证与实机待验

新增 8 个回归场景：四步序列、重复次数与重复成功、失败/其他技能/受限或缺失起始、跨战斗起手、起始先于公开读条、暂停/设置/重置、未知战斗状态，以及待命请求和脱战最终信号保持零输入。

项目检查、237 项 Lua 模拟、235 项 pytest 测试及 17 项子测试、两套 unittest、Python 编译检查和 40 个 Lua 文件的 Lua 5.1 语法检查通过。离线结果不证明实机施法或输入成功。

首轮 pytest 的既有桌面工作线程退出测试在固定 50 毫秒等待后仍读到 Starting；该用例单独复核及完整重跑通过。本次未改动桌面运行代码或该测试。

实机验收：配置 A→B→C→D，启用自动模式，脱战手动施放 A，确认 HUD 转到 B；进战确认从 B 接续。另检查 A×3、手动起手导致进战、失败后重试，以及主动暂停和打开设置期间不计数。现有目标／战斗循环重置规则继续生效。
