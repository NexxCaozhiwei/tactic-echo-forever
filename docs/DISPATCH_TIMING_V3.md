# 接续审计与独立延迟设置

日期：2026-11-09。版本保持2.0.1；继承[联合测试候选](DISPATCH_TIMING_V2.md)及[实测日志检查](DISPATCH_TIMING_LOG_REVIEW_20261109.md)。本轮完成代码审计与修正，不提交、不推送；客户端效果仍待复测。

## 审计发现及处理

| 问题 | 影响 | 本轮处理 |
| :--- | :--- | :--- |
| 奥术愤怒没有语义类型登记 | 不能成为读条末尾预载候选，日志出现214～297毫秒的成功至下一起手间隔。 | 增加普通读条类型登记；名称仅用于分类，每次资格仍要求精确ID公开已学，未知仍阻断。保留范围、资源、目标、策略及绑定复查。 |
| 队列没有起始身份时，用同ID失败事件替代队列身份并撤销 | 一次无关失败可能取消有效预载。 | 未关联终态只封存自己的GUID，不撤掉其他预载；关联队列精确失败仍撤回，精确成功仍控制推进。 |
| 下一技能为引导时，资格依赖当前引导截断开关 | 普通读条接飞弹也要等结束后请求。 | 下一技能是已知引导类型时，可由普通读条窗口预载；提前结束当前引导仍由独立开关、身份及公开时间保护。地面引导、未知类型、魔杖仍不预载。 |
| 普通与组内窗口共用参数、开关存在隐含依赖 | 无法单独调节技能组；容易误判设置含义。 | 技能组开关、提前量、模式和网络补偿均独立；组内引导还需开启技能组开关，组外引导需开启普通开关。 |
| 组末引导成功后，跨轮仍强制等待引导完全消失 | 即使显式允许末尾介入，也不能在组末使用该窗口。 | 仅在已接受精确成功且还有下一轮时允许按引导窗口接续；切轮与恢复运行时保留已确认的引导身份，最后一轮不提前进入父列表。 |
| 设置提示仍写不跨组、不预测APL或引导 | 文案与实现冲突。 | 按五个卡片重新组织设置，全部延迟数值显示毫秒，明确适用来源及生效时机。 |
| 历史窗口剩余量缺少采样时间 | 非窗口事件可能被旧数值误导。 | 日志增加采样时刻、样本年龄和普通／组内／引导类别；不同引擎或代次不复用窗口数据。队列记录保留自己的窗口样本。 |

## 按键时机与效率

按公开施法生命周期与客户端窗口确定时机，不加入随机等待、拟人抖动或正常技能间的固定停顿。确认起手就撤掉当前请求，成功才推进。只有下一技能资格已知且窗口合法时提前请求，不靠重复旧技能接续；失败重试间隔不参与正常成功接续。

仍沿用现有心跳、TEAP v3与TEF TEK输入链，不查询GCD/61304，不新增定时器、钩子、输入程序或宏。世界延迟最多每秒采样一次，无逐帧法术书扫描。TEK的真实手动输入与频率门禁保留；本轮不保证零间隙，也不把正常客户端等待当成插件延迟。

## 设置含义与迁移

位置：`/tefui` → 高级TEK。设置打开时禁止派发；修改接续参数后，关闭设置并手动重新开启。

| 设置 | 范围及含义 |
| :--- | :--- |
| 普通读条接续 | 固定列表与自定义APL；独立开关。自定义提前量0～500毫秒，0等待当前读条结束。 |
| 技能组读条接续 | 组内换步、跨轮；独立开关。自定义提前量0～500毫秒，不跨父列表。 |
| 提前量来源 | 普通与技能组各自选择“自定义提前量”或“跟随客户端窗口”。跟随模式使用公开客户端窗口且最多500毫秒，自定义数值不参与、输入禁用。客户端窗口0或未知时不提前排队。 |
| 网络补偿 | 普通与技能组各自开关、各自设置0～150毫秒的额外补偿上限。仅自定义模式参与：补偿为世界往返延迟的一半与上限的较小值；有效提前量再受客户端窗口及500毫秒限制。未知延迟不添加补偿。 |
| 引导末尾介入 | 默认关闭，提前量0～500毫秒，0等待自然结束。默认50毫秒，不叠加网络补偿；可能截断最后一跳。 |
| 失败重试间隔 | 0～500毫秒，默认150毫秒，仅针对已确认失败；0为下次心跳，不保证立即按下。 |

旧配置的普通提前量、引导提前量与开关保持原值；新增组内提前量继承旧普通提前量，组内网络开关继承旧网络开关。已有引导200毫秒不会被静默改成50毫秒。新建配置和旧配置缺失的模式均为自定义；额外补偿上限默认150毫秒。受限值、非法模式及越界输入不会被当作就绪资格。

## 推荐复测

1. 先关闭引导介入，普通及技能组接续均开启；两者先选跟随客户端窗口，客户端值保持原样。
2. 复用原组中的奥术冲击 → 奥术愤怒，以及寒冰箭 → 奥术愤怒；比较下一技能是否在前一读条尾部提出请求，是否减少日志中214～297毫秒的接续间隔。
3. 测试奥术愤怒 → 火焰冲击 → 飞弹。区分瞬发成功后客户端仍不接受下一技能与插件未提出请求，不用失败事件推测公共冷却真值。
4. 技能组两轮、连续同ID、精确失败、移动及切目标分别测试；进度不得提前、多算或因无关失败卡住。
5. 记录关闭引导介入时的完整跳数，再以20毫秒、50毫秒对照；200毫秒已有缺末跳风险证据，不作为推荐值。不以接续更快代替最后一跳验收。
6. 测试结束再 `/reload` 或退出游戏落盘，核对窗口样本年龄、提前请求、起手与精确成功。
