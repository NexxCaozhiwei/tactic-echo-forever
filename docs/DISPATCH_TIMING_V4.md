# 接续预热、尾窗检测与分段送达诊断

日期：2026-11-09。版本保持2.0.1，继承[上一轮设置](DISPATCH_TIMING_V3.md)及[会话123复查](DISPATCH_TIMING_LOG_REVIEW_SESSION_123.md)。用户完成本轮测试，反馈暂未发现问题，并授权提交及同步；尚未提供逐项跳数与接续耗时结论，不将反馈扩大为全部场景验收通过。

## 已实现行为

### 候选提前准备

在现有心跳中，每个活动施法最多每0.20秒只读准备下一候选及绑定。固定列表与技能组计算下一项及组内下一轮；自定义APL只读求候选，复用同代次、同回执、同版本且未过期的预览样本，避免与原预览重复完整采样。

预热不创建请求、不发布Token、不替换当前推荐、不消费额度、不推进计数。进入真实尾窗后，仍由现有Runtime和Dispatch检查目标、技能精确已学、范围、资源、策略、绑定和实时施法状态。过期、目标改变、代次或回执变化时，不使用旧候选授权输入。引导APL在允许窗口开放后可复用有效的预热样本，仍重新求值及实时复查。

### 窄尾窗检测

复用原传输逐帧回调，只增加公开时钟与已准备截止点的轻量比较。正常完整处理仍按50毫秒心跳执行；在截止点到达时，每个截止点可额外唤醒一次相同的处理函数，不等待下一次完整心跳。

逐帧检查不扫描候选、法术书或绑定，不新建计时器、钩子或输入路径。不扩大用户配置或客户端窗口，不把浮点容差当作额外截断预算。起止时间更新或窗口变化后重新准备截止点；未知时钟、旧代次、旧目标或暂停后的计划不唤醒。

### 引导停止后的接续

公开玩家引导停止事件处理完毕后，立即复用同一个传输处理函数，执行推荐、门禁、请求和信号绘制。停止事件只撤销事件锁，不制造“施法为空”；实时接口仍显示引导、受限或未知时继续阻断。只有公开消失或进入显式允许的尾窗时，才可能提出下一请求。

完整5跳、实际伤害及服务器接续仍需实测，不保证单凭停止事件就实现零间隙。50毫秒默认值及用户原有提前量均未被自动调大。

## 送达诊断

### 插件侧

新增独立的 `TEF_DB.deliveryDiagnostics`，最多128段。每段保存请求编号、精确技能、会话、代次、绑定Token，以及首次／末次发布的既有序号和新鲜度身份、请求／发布时间及对应公开起始时间。连续发布合并成一段，信号中断则新建一段；每段最多4096帧，支持16位回绕。加载时经Safety净化，诊断从不参与输入门禁。

该记录与512条状态日志分开，重复状态不会直接挤掉它。可以在插件同一时钟内测量“请求到首次发布”和“请求到对应起始”；起始事件不等于证明某次TEK输入成功。

### TEK侧

新诊断候选保留帧读取开始／完成、前台复查耗时、处理耗时及派发开始／完成时刻。`observedAt`使用实际读取完成时间；`writtenAt`另记序列化时刻，避免把异步队列和成功摘要延迟误认为送达延迟。成功摘要保留首帧与末帧的身份及首帧阶段时间。

仍保留前台、真实手动按住与释放、新鲜度、CRC、重放、频率和每次单次SendInput保护。本轮未提高发送频率、未自动停止或替换活动TEK；候选仅构建，不启动第二实例。

### 离线关联

使用 `scripts/analyze-delivery-timing.py`，按会话、绑定Token及对应的序号／新鲜度区间关联日志，冲突时报告歧义，不猜测归属。脚本只读取指定TEF_DB与TEK日志，不写WTF。

```powershell
python scripts/analyze-delivery-timing.py --saved-variables "C:\Program Files (x86)\World of Warcraft\_forever_\WTF\Account\VINZCN\SavedVariables\Tactic Echo Forever.lua" --trace "C:\Users\CZW\AppData\Local\TacticEchoForever\logs\tek-trace-20261109.jsonl" --output dist/tef/delivery-timing-analysis.json
```

输出包括插件请求至发布／起始、TEK读取／前台复查／处理／派发耗时及保留记录中首次识别至首次发送的等待。成功摘要和限流记录均可能合并或缺失，结果只代表已保留的证据。

两端时钟起点未经校准，不能直接用TEK墙钟减去插件GetTime，宣称得到精确的插件到TEK单向耗时。本轮提供帧身份关联与各段同端测量，仍以插件请求至真实起始验证整体接续效果；旧TEK日志缺少新阶段字段时，报告未知，不补造数值。

## 部署与联合测试

插件优化兼容当前TEK，重新加载即可使用。完整TEK阶段诊断需要手动退出当前TEK后，运行独立候选 `dist/tef/handoff-diagnostics-20261109-v4/TEK-TEF.exe`；不得同时运行两个输入实例。构建跳过启动冒烟，避免干扰当前实例，不据此宣称钩子或真实输入验收通过。

1. 保持原参数：普通150毫秒、技能组300毫秒、引导50毫秒；先不改窗口，复用同一技能组对照。
2. 稳定目标、停止移动，观察飞弹至奥术冲击／寒冰箭，以及普通读条至奥术愤怒。与上一轮引导336、226、121毫秒间隙比较，逐段核对5跳。
3. 检查 `HANDOFF_PREPARED`、`HANDOFF_TAIL_WAKE`、`CHANNEL_STOP_RECONCILE` 及独立送达记录。没有有效实时信息时，额外唤醒不能产生Token。
4. 再分别测试移动、切目标、设置、暂停、Secret、失败、组内跨轮与同ID，确认旧计划无输入资格，次数仍由精确成功推进。
5. 结束后重新加载或退出游戏落盘，再运行关联脚本；TEK候选未切换时，读取／派发等新增阶段保持未知。
