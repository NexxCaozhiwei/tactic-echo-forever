# 普通读条持续派发改版草案

本改动纳入1.1.0基线，开发阶段在1.0.23工作区验证。参照原TE的普通推荐持续输出方式，修改插件端请求保持；TEK程序、线协议及频率门禁不变。

## 新行为

- 默认启用普通技能持续输出。普通读条不再统一撤销当前推荐Token，公开SENT/START建立回执身份但保持请求。传输继续逐帧更新序号，由既有TEK门禁控制实际发键。
- 固定序列仍只在精确成功时计数和切步；重复发键或公开起始不增加次数。成功后撤销旧推荐输出，再复核下一步。
- 引导开始立即撤回输入并建立事件锁；引导结束只解除事件锁，实时UnitChannelInfo仍必须确认无引导。Secret、缺失、调用失败继续阻断。世界切换清除旧事件锁并依赖实时查询重新判断。
- 魔杖5019、攻击6603、自动射击75继续使用原开启状态和交接门禁，不采用普通技能连发。
- 自定义APL仍保留精确候选、条件、快照和回执保护；持续输出不会允许不满足条件的规则输入。
- 不绕过焦点、目标、距离、资源、绑定、设置、战斗模式或限定使用策略。不可用跳过不得跳过已起始回执。
- 已启用的末尾排队继续在配置窗口内切换到下一步。即使关闭末尾排队，人工同技能还有次数时，客户端提前接受的下一次精确起始也保留独立未来回执；当前成功前不计数，失败不取消原起始。

## 兼容与诊断

内部ordinaryContinuous标量默认true，用于迁移新行为；显式false保留旧单次尝试机制，既有回归通过该模式继续验证。不是新增界面选项。受限或无效的已存标量不授权新行为。

记录ORDINARY_CONTINUOUS_INITIATED、ORDINARY_SAME_SPELL_NEXT_RESERVED及原Token发布/回执诊断。插件输出不等同于真实SendInput次数。程序可能仍因安全门禁不发键；不要用请求数量估算实际按键数量。

## 验证重点

回归覆盖普通读条持续Token、成功切步、额外失败隔离、引导/未知立即撤回、SENT早到的同ID未来回执及自定义APL持续候选。实机尚需确认：普通施法期间按键持续，人工次数准确，引导完整保留，被打断后恢复，暂停即时归零，魔杖已开启不重复触发。

建议先关闭末尾提前排队，人工方案使用837×1 → 145×2 → 5143×1，不循环、不可用跳过关闭；同一目标站定运行30–45秒，随后暂停并reload落盘。再开启0.35秒排队做对照。不要同时修改其他设置。
